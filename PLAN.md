Primary outcome is warm c1 generated tokens/s on actual Pi turns. Secondary outcome is wall time to a correct ordered read, exact edit, test and final answer. Use an isolated Pi 1.6.0 fixture, loopback only, deterministic sampling, 512 tokens per agent response and the full three-pass loop. Direct tests target 2,048 and 8,192 input IDs and 256 outputs. Context target is 32,768. Qualify with a separate held-out task, half/full-context retrieval and a sustained session. Compare candidate legs against both adjacent controls with six samples per leg, then check greedy equivalence and the 3% regression limit.

Six scored independent Pi tasks per leg, following one warm-up per process. The target weights and greedy generation settings stayed fixed. All 18 tasks passed. Each initial request had zero cached input IDs. Every completed task used 223 generated IDs across five model responses.

Depth 6 improved decode by about 49% over both adjacent controls and saved about 3.6 seconds per complete task. Its first-token delay grew by 2.92% and 2.99%. The bootstrap ratios for first-token delay extend slightly beyond 3%, so that metric sits at the promotion threshold. The fresh-code panel also regressed. The other five returned the expected code. Follow-up qualification uses a 768-ID allowance for retrieval. Agent budgets remain fixed at 512.

Enabling oMLX's own paged prefix cache changed the outcome. With the same native target, plain oMLX passed the primary task in 18.49 s and the untouched held-out task in 19.00 s. Each new process started with its own disposable cache and no shared prefix from a previous trial. The following controlled trials must reproduce this initial cache condition.
