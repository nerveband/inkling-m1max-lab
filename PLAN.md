## Speed experiments after the registry gate

Each screen below advances a different execution change using one actual local Pi task. The control with fresh task prefix is native oQ4e at 38.17 generated tok/s and 15.09 s per correct task. Changing the oQ4e expert sorting threshold from 64 indices to 32 reached 39.15 tok/s in 14.98 s. Compiling the weighted expert reduction reached 38.24 in 15.11 s. Casting the BF16 inventory to FP16 reached 46.24 and casting only the expert path reached 49.61, but both emitted punctuation and executed zero tools. Power-of-two rescaling recovered useful text but failed a tool. Narrowing the precision change to loop controllers passed at 35.44 in 15.62 s. The model always ran all 48 visits.

A real difference in first-token latency came from the cache snapshot boundary. An unrelated primer containing the same tools still gave zero cached IDs on the next task. Instead, two synthetic user strings identify the token prefix shared by the system and tools. Priming one token past that boundary lets this stateful engine retain the exact common prefix. On oQ3e it reused 1,363 IDs, reducing first-token delay from 5.15 to 0.87 s. Priming cost 4.89 s once. The correct task then ran in 8.33 s at 39.64 tok/s, versus 12.78 s at 38.67 on the same quant with a fresh prefix. Both produced 178 IDs and went directly from read to edit to test. A 32-index sorting threshold with the same warm prefix reached 40.94 tok/s in 8.16 s in one screen.

The lower oQ2.5e checkpoint was slower at 25.54 tok/s and 16.10 s fresh, and 25.36 tok/s and 9.97 s primed. A separate oQ4e experiment converted FP4 experts to affine four-bit blocks during model load. It delivered 39.55 tok/s and 12.50 s fresh, and 39.55 tok/s and 8.27 s primed. All four edits passed. The 8.27 and 8.16 s wall times are within the three-percent threshold in individual speed screens. The published launcher uses the native three-bit checkpoint and avoids load-time expert conversion. The clean-checkout three-bit primary and held-out edits delivered 39.64 and 40.45 tok/s without an intentionally seeded first prefix. [All speed screens](raw/speed-screens.json)

The clean-checkout oQ3e finalist passed reasoning, the original and held-out coding tasks, exact retrieval at 31,954 and 64,717 input tokens, and all 12 HTTP conversation turns. It returned a reasoning-only completion on each of the first two reopened Pi turns with tools disabled; turns three through six returned the exact code. The four-bit fixed-depth-6 setup is the fastest fully Pi-qualified configuration. The three-bit result is the fastest correct primary edit measured. Its independent registry attempt is recorded separately.
