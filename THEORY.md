# Device ceiling estimates

Median timed Metal blit traffic was 309.46 GB/s (read plus write). Median 4096-square MPS FP16 GEMM was 5.462 TFLOP/s. Each median uses seven warmed GPU command-buffer timings. Copy rate is a proxy for streaming reads. MPS dense GEMM is a proxy for quantized MoE compute.

The tensor offsets include quantization scales, blocks and alignment. Per visit, charge 8/128 of each expert bank, dense attention, routing and one full vocabulary projection per token. Count one input embedding row. The low-traffic bound assumes perfect reuse of the same expert selection and dense weights across repeated visits. The high-traffic case streams weights afresh on all 48 visits. Actual routed expert reuse and physical DRAM traffic are unknown.

For FP16 KV, 40 local visits read at most 1,024 positions and eight global visits read the whole context. Each position has eight 128-wide K and V heads. GQA reuse is assumed. Activation traffic, cache writes, kernel launches and quantization conversion reduce attainable rates. Prefill uses twice the active tensor elements per visit plus causal attention dot products over the average span. The 50% efficiency factor is an assumption. These ranges are planning estimates, not measured model speeds.

The 2K blank-slate visible-code screen reached 18.50 tok/s on copied code and 18.67 tok/s on fresh code. Its measured prefill rate was about 170 tok/s. The gap to the traffic estimate includes Metal command-buffer waits observed in short host samples. The hardware counters available to this experiment do not identify the fraction of the gap due to physical DRAM transfers. Proposal acceptance changes the work per emitted token substantially.

For the five model responses in the 64K profile’s warm coding task, native oMLX verified 154 of 167 proposed IDs (92.2%). It counted 223 emissions including five stop IDs. The API counted 218 generated IDs. Instrumented component totals were 6,145.8 ms for target-backbone work, 116.1 ms for drafting, 2.5 ms for sampling and 12.3 ms for cache operations. The target accounted for 97.9% of summed component time. GPU work can overlap these timers. Prompt evaluation was a separate cost and first-turn time to first token reached roughly 5.4 s. This profile locates the cost in target evaluation. Physical DRAM throughput, per-expert cache misses and individual Metal kernel durations remain unmeasured.

At fixed depth 6, the first scored independent process accepted 176 of 190 proposals in the five-response Pi task. It counted 223 emissions with stops and 218 API-generated IDs. Summed native timers were 5,432.6 ms target, 175.3 ms head, 1.7 ms sampling and 12.8 ms cache work. Target evaluation took 96.6% of that instrumented sum. The deeper draft spent 59 ms more in the head but saved roughly 713 ms on target evaluation compared with the depth-3 diagnostic above. These comparisons are from separate processes.

The fastest correctly completed three-bit Pi screen used four model responses. It accepted 142 of 156 proposals in 32 cycles and emitted 182 native IDs including four stops (178 API IDs). The instrumented totals were 4,103.5 ms target backbone, 132.8 ms draft head, 1.8 ms sampling and 11.8 ms cache handling. The backbone was 96.6% of their sum. ## M1 Max kernel stack breakdown (`m1-full-affine4`)

On the promoted M1 Max stack (`omlx-oq4`, load-time `affine4` group-size-64 expert conversion plus `M1_FAST_FEATURES` at fixed depth 6), the primed 4-response Pi screen (`178` API IDs, `141/157` accepted in `33` cycles, `4.82 s` prime, `1,363` cached IDs, `0.79 s` TTFT) dropped total backbone time from stock `oQ4e` depth 6's `5,432.6 ms` (5 responses) and `oq3+sort32`'s `4,103.5 ms` down to **`3,323.2 ms` (`100.7 ms/cycle`)**, with **`125.4 ms`** draft head, `1.9 ms` sampling, and `11.1 ms` cache work (`7.14 s` wall, **`49.43 tok/s`**). The ordinary direct-provider launch on clean idle GPU hit **`50.08 native-window tok/s`** on `omlx-oq4` (`9.39 s` over 5 turns, `208` net IDs in `4.153 s`) and **`49.38 native-window tok/s`** in **`7.28 s`** on `omlx-oq3` (`174` net IDs in `3.524 s`, `-892 ms` backbone vs `public-oq3-pi` `39.67 tok/s, 8.48 s`). [Promoted primed counters](raw/speed-m1-final-affine4/mtp.json)

Why these choices won on `applegpu_g13s` (24 GPU cores, 400 GB/s):
- **`affine4` > `nvfp4` & `oq3` on verify**: MLX Metal `gather_qmm` unpacks 2 clean nibbles per byte for `affine4` (`group_size=64`) without NVFP4 `E2M1/E4M3` LUT unpacking overhead (`9.62 s / 42.26 tok/s → 7.14 s / 49.43 tok/s`) or 3-bit cross-word bit-stitching (`100.7 ms/cycle` vs `104.8 ms/cycle` on `oq3`), while keeping 4-bit precision (`6/6` reopened Pi turns passed vs `4/6` on `oq3`).
- **`fast_decode` + `split_in_proj` + `verify_compile` + `m1_attn`**: Collapsing tiny conv/clip/msg/SwiGLU/combine ops and using split-K `verify_banded_sink_attention` (`nsplits <= 64` at 32K–64K) cut per-cycle overhead by `~38%` over stock `oq4` (`3,323 ms` / `33 cyc` vs `~5,433 ms` / `~37 cyc`) and boosted long-context decode (`30.02 vs 21.04 tok/s` at 32K, `20.19 vs 15.87 tok/s` at 64K) while cutting peak GPU memory at 32K from `36.41 GB` down to `32.06 GB`.
- **`prefill_pad64` + `skip_lm_head` + `fast_greedy`**: Zero-padding `28..63` token batches in `Inkling2Experts` triggers MLX's tiled `gather_qmm` GEMM instead of GEMV during prime/prompt chunks (`-0.31 s` Pi wall); skipping prefill logits (`skip_lm_head`) and avoiding redundant vocab-wide `logsumexp` during greedy verify (`fast_greedy`) trimmed host/GPU synchronization.
- **Depth 6 vs Depth 3**: Depth sweep under `CORE + fast_decode` measured `d3=32.89`, `d4=35.95`, `d5=36.71`, `d6=48.74–49.01`, `d7=37.10 tok/s`. Depth 6 maximizes tokens/cycle relative to backbone verify cost (`M=7` stays below MLX's small-batch GEMM knee while amortizing depthwise conv/attention across 7 tokens).
- **Why `LookAtMyQuant` and AMD Loom techniques differed on M1 Max**: Without M5 Neural Accelerators (`_has_mpp()` is `False`) and with an `832` threadgroup limit (`sg=32` crashes on M1 Max), `LookAtMyQuant`'s trellis+RHT kernels are ALU-bound at `59–63 ms/step` serial and `121–128 ms/check` drafted (`26.06 tok/s` peak code, `22.92` agent-edit, `16.01` prose). Meanwhile duplicating a 4-bit draft LM head alongside the 8-bit target head (`loom_draft_head`) reduced `head` time (`125.4 → 97.9 ms`) at a net backbone penalty (`3,323 → 3,663 ms`), yielding `43.83 tok/s`.
- **Background GPU sensitivity**: Because unified-memory LLM inference on M1 Max is bandwidth-bound (`400 GB/s` shared with macOS WindowServer and GPU apps), an observed `52–62%` idle desktop GPU load (`1.3–2.0 GB` residency) during mid-session trials reduced even unmodified stock `oQ4e` by `21%` (`37.87 → 29.92 tok/s`) and `--m1-fast --affine4` from `49.15` to `39.92 tok/s`. Clean comparisons verify `AGXAccelerator` idle utilization `< 20%` (`0%` in clean runs).
