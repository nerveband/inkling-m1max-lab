# Inkling 2 Mini on M1 Max, 21 November 2026

The fastest correct representative Pi turn observed on this 24-core GPU, 64 GiB M1 Max used oMLX 0.8.2, the native oQ3e checkpoint and its bundled DSpark head at fixed depth 6. It read the file, edited it, ran the test and returned the exact answer in **8.16 seconds at 40.94 generated tok/s**. The engine had the project's shared system and tools prefix cached. A fresh-prefix run of the same launcher from a clean checkout delivered **39.64 tok/s in 12.61 s**, and the held-out task delivered **40.45 tok/s in 12.90 s**. Each is one correct coding task. The three-bit model later missed two of six reopened Pi turns; use the native four-bit depth-6 profile for the fastest result that passed every agent qualification gate. The highest-throughput repeated-code workload used a different configuration. ## Where the time went

The shared-prefix preparation took 4.88 s. It reused 1,363 prompt IDs on the first scored request. First-token latency was 0.86 s and subsequent client first-token latencies were 1.08, 1.69 and 0.82 s. The four replies contained 178 generated IDs, including 39 reasoning IDs. The endpoint groups ordinary text, structured tool calls and protocol IDs together for the remaining count. The 8.16 s includes Pi startup for the task and tool execution. Adding the raw primer yields 13.04 s, so priming pays off for later tasks that reuse the same system and tool prefix. Different projects and tool definitions can change that prefix. [Priming measurements](raw/speed-oq3+sort32+aligned/prefix-prime.json) · [turn counters](raw/speed-oq3+sort32+aligned/pi-scores.json)

On the primed three-bit winner, the target accepted 142 of 156 proposals. Native counters reported 182 emissions, including four stops. Target work took 4.104 s and drafting took 0.133 s. Target evaluation accounted for 96.6% of summed component time. The screen peaked at 14.02 GiB process RSS and 16.94 GiB system-wide GPU residency, with zero swap growth. These memory values overlap. [Finalist native counters](raw/speed-oq3+sort32+aligned/mtp.json) · [memory samples](raw/speed-oq3+sort32+aligned/monitor.jsonl)

On one oQ4e depth-6 Pi task the draft proposed 190 IDs, the target accepted 176, and the engine emitted 223 including five stops. The API reported 218. Native timers accumulated 5.433 s of target work, 0.175 s drafting, 0.002 s sampling and 0.013 s cache work. The target accounted for 96.6% of those component times. The timers can overlap. Individual expert cache misses and physical DRAM reads were unavailable. Measured Metal copy bandwidth was 309.46 GB/s and FP16 GEMM throughput was 5.462 TFLOP/s. With 48 layer visits, the GGUF traffic model gives single-token decode ceilings of 68.8 to 115.1 tok/s at 8K and 58.4 to 88.6 at 32K. Estimated prefill at half measured GEMM throughput was 265, 255 and 229 tok/s at 2K, 8K and 32K. ## Direct workloads and unsuccessful speedups

On exact 2K and 8K inputs requesting 256 generated IDs, GGUF DSpark 6 achieved 33.98 and 32.08 tok/s on copies, and 16.17 and 11.36 on fresh code. The oQ4e depth-3 native direct screen reached 37.99 and 28.07 on copies and 27.05 and 23.30 on fresh code. The full 2K/8K direct panel was not repeated on the three-bit Pi finalist. [GGUF panels, including prefill and first-token times](raw/direct-comparison.json) · [oMLX native clocks](raw/app-oq4-fixed3-direct/native-clock.json)

The 114.39 tok/s copy median depended on high n-gram acceptance (1,499 of 1,592 proposals). Five of six copied outputs matched both controls token for token. The sixth added an introduction. The configuration scored 15.44 tok/s on a fresh-code screen and 24.69 tok/s in 19.74 s on the Pi task. Native speculative reasoning also diverged from greedy draft-off text on a diagnostic. Quant changes and speculative decoding have no general output-equivalence claim here. [Copy benchmark](raw/copy-final-comparison.json) · [quality checks](raw/copy-candidate)

Three-bit oQ3e beat two-and-a-half-bit oQ2.5e on this GPU. The latter achieved 25.54 tok/s fresh-prefix and 25.36 primed. FP16 expert casting printed punctuation at 49.61 tok/s and ran zero tools. TensorFold leaked tool markers. MLX-LM required a parser patch and oMLX rejected the same MLX-LM weights. NetProjects affine four-bit with drafting and caching reached 25.22 tok/s. No matching runnable Mini head or single-M1 path was established for Tencent DSpine, DFlash 2, EAGLE-family heads, an ANE split or EXO's advertised M5 results. ## Qualification and registry

The native oQ3e and oQ4e depth-6 launchers both separated reasoning correctly, passed the held-out tool task, and retrieved three ordered keys on each of the 31,954- and 64,717-token prompts. In the clean three-bit run the loopback model list became ready after 4.28 s. The first inference separately reported 16.97 s to load weights. Filesystem cache state was uncontrolled. On the three-bit model, near-full context took 287.58 s, with 234.81 input tok/s and 13.36 generated tok/s (159 IDs). The half-context prompt produced 19.86 tok/s. Both profiles passed all 12 turns of an accumulating local HTTP conversation. The two configured slots were tested with one active stream. At 128K the four-bit profile exceeded the model memory preflight allowance, and the independent run also stopped when macOS memory pressure rose. The highest qualified window for the four-bit setup was 65,536 per sequence. [Three-bit retrieval](raw/qual-oq3-d6-sort32/needles.jsonl) · [four-bit qualification](raw/registry-64k-d6) · [128K evidence](raw/registry-128k-independent)

On native oQ4e at depths 3 and 6, all six reopened Pi turns returned the original session code. The three-bit depth-6 candidate returned reasoning without a visible answer on turns one and two, then returned the correct code on all four remaining turns. Pi sent the full message history on every turn. These six turns used Pi's no-tools mode. The fastest configuration satisfying every Pi gate was **oQ4e depth 6 at 38.17 tok/s**. The three-bit speed screen remains the fastest observed correct edit. Quantization changes the target and these fixtures do not establish general coding quality.
